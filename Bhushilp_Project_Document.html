⛏️ Real-Time Fleet Monitoring and Operational Analytics Platform for Kamptee Opencast Coal Mine

The Problem Statement

Overburden (OB) rehandling operations at Kamptee Opencast Coal Mine are constrained by fragmented data collection, limited real-time visibility, and reactive maintenance scheduling. Current operations lack integrated telemetry from vehicle fleets, making it difficult to optimize haul cycles, predict equipment failures, monitor fuel efficiency, and plan preventive maintenance. The absence of centralized operational dashboards and historical analytics limits the mine's ability to improve productivity, reduce operational costs, and ensure timely equipment servicing. Field data is collected across multiple sources—manual logs, disparate telematics endpoints, and service records—creating silos that prevent holistic operational insight.

Solution

This project will develop an end-to-end MERN stack platform that integrates real-time vehicle telematics from the VECV Partner API with operational data management, live fleet visualization, and predictive analytics to enable efficient OB rehandling at Kamptee Opencast Coal Mine. The platform ingests Location, Fuel, Service History, and Alert streams from active Eicher-manufactured vehicles, processes multi-source geospatial and operational data through standardized pipelines, and presents unified dashboards for real-time fleet tracking, performance analytics, and maintenance planning. Features include live GPS-based vehicle positioning on satellite maps, dynamic KPI monitoring (total OB moved, revenue generated, operational costs, trips completed), fuel consumption tracking, service history correlation with equipment condition, and predictive alert aggregation from vehicle diagnostics. The overarching objective is to centralize operational visibility, reduce non-productive time, extend equipment life through timely maintenance, optimize haul logistics, and provide data-driven decision support for mine planning and scheduling.

Objectives

  1. Design and implement a MERN-stack platform with JWT-authenticated access, multi-mine project isolation, and role-based dashboard views for dispatchers, fleet managers, and maintenance engineers.
  2. Integrate the VECV Partner API (Location, Fuel, Service History, Alerts modules) to ingest real-time and historical telematics for all Eicher-manufactured vehicles (tippers, excavators, dozers) operating in OB rehandling cycles.
  3. Establish standardized data models and ingestion pipelines for vehicle state, trip records, fuel consumption, service events, and predictive alerts, with support for mixed real-telematics and simulated data during rollout.
  4. Develop live map visualization with real-time vehicle positioning, geofence boundaries (Area A excavation site and Camp Yard dump point), and animated route tracking at 45 km/h average haul speed.
  5. Construct operational dashboards displaying real-time KPIs (total OB volume moved, revenue, cost, trips) alongside historical trend analysis (daily production, average trips per day, equipment utilization).
  6. Implement alert aggregation and acknowledgment workflows for vehicle faults, maintenance due dates, fuel anomalies, and service recommendations derived from VECV telemetry.
  7. Create service history and maintenance log interfaces to correlate workshop service records with vehicle performance degradation and plan preventive interventions.
  8. Enable scalable multi-mine architecture where new mining operations can be onboarded with minimal code changes via configuration-driven database isolation and project registry patterns.

Methodology

Data Acquisition & Integration

Real-time and historical data are acquired via the VECV Partner API, which supplies Location (GPS, speed, vehicle status), Fuel (consumption, level, engine hours), Service History (dealer records, parts, labor costs), and Alerts (predictive maintenance, fault codes) for all registered Eicher vehicles. Vehicle data is supplemented by internal operational records (trip logs, driver assignments, equipment metadata) stored in a MongoDB project-specific database. All external telematics are ingested through a unified, idempotent ingestion endpoint that tags records with source (seed data, manual input, telematics), external reference IDs, and timestamps for traceability.

Data Standardization & Storage

A standardized Mongoose schema hierarchy models vehicles (with chassis number and data source flags), trips (haul cycles from Area A to Camp Yard), fuel logs (consumption snapshots), GPS logs (position with vehicle status), maintenance records (workshop service events), alerts (vehicle diagnostics), and service history (job card details). MongoDB's multi-database support via useDb() enforces project isolation—each mine's operational data (e.g., dummy_kamptee_fleet or fleet_kamptee) remains independent while cross-project users are stored centrally in bhushilp_platform. Rate-limited polling of the VECV API (≤1 request/minute per endpoint) is orchestrated by a background poller that runs only when API credentials are configured and vehicles are onboarded to live telemetry.

Visualization & Real-Time Analytics

The frontend displays live fleet state on Esri satellite maps with color-coded vehicle markers (green for loaded haul leg, blue for empty return leg), geofence overlays, and interactive popups showing real-time GPS, speed, and vehicle status. For vehicles onboarded to VECV telemetry, real GPS positions override simulated positions; vehicles on the simulation path continue to animate deterministically based on haul cycle timing. KPI cards present aggregated metrics (total OB, revenue, cost, trips) and trend charts (daily production over time, average trips per day) derived from trip aggregation pipelines. Alerts and service history are displayed in scrollable feeds with acknowledgment controls, enabling dispatchers to respond to vehicle issues and maintenance engineers to plan workshop interventions.

Validation & Scalability

A smoke-test script validates VECV API connectivity, token acquisition, and header requirements before production deployment. Spatially aware validation compares telemetry-derived positions and timing against historical trip records to ensure data quality. The architecture supports gradual fleet onboarding—vehicles are transitioned from simulated to live telemetry by updating a single database field (data_source: "vecv_live" and chassis_number), enabling A/B comparison and phased rollout without code changes or redeployment.

Deliverables

1. Full-stack MERN Application

  • Backend: Express.js REST API with JWT authentication, project-scoped routes, multi-database isolation, and VECV API integration
  • Frontend: React dashboard with live map, KPI cards, trend charts, alerts, and service history components
  • Deployment: Deployment-ready code with environment variable configuration for multi-mine support

2. Data Ingestion & Polling Infrastructure

  • VECV Partner API client modules (Location, Fuel, Service History, Alerts)
  • Background poller with configurable rate-limited polling and upsert logic
  • Standardized Mongoose schemas with external reference tracking for idempotent ingestion
  • Smoke-test and onboarding scripts for validation and fleet configuration

3. Operational Dashboards

  • Overview tab with live map, real-time KPIs, and trend analysis
  • Fleet Operations tab with vehicle state table, alerts feed, and service history
  • Drivers tab with assignment and performance tracking
  • Cameras tab for event logging and incident review

4. Geospatial & Telemetry Visualization

  • Interactive satellite map with real-time vehicle positions, route overlays, and geofences
  • Dynamic vehicle markers distinguishing live (white ring) from simulated (default) positions
  • Popup details showing GPS, speed, vehicle status, and data source indicators

5. Technical Documentation

  • Architecture overview and system design document
  • API specification and integration guide for VECV telematics
  • Deployment guide with environment setup and MongoDB configuration
  • Database schema reference and field mappings from VECV API
  • Operational runbook for alert handling, maintenance workflows, and fleet onboarding

6. Multi-Mine Platform Foundation

  • Project registry and configuration system for new mine deployments
  • Database isolation patterns enabling simultaneous operations across multiple sites
  • Role-based access control and JWT-authenticated API endpoints
  • Extensible ingestion pipeline supporting future telematics sources
